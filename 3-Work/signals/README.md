# Signals

Working memory for a day you actually filed something. One file: `YYYY-MM-DD.md`. Append a bit. Do not open a new file per sentence.

A bit is an alignment, a nudge, a fact you picked up, or a small call. It changes what you believe about a person, a bet, or a decision. It is not a task and not a diary of what you did.

**File a bit through the `capture` skill.** The bullet shape lives in `.claude/skills/capture/references/template.md`. This folder does not keep a second copy.

## Four types

| Type | What belongs |
|------|----------------|
| info | A fact you picked up that might matter later |
| alignment | Who moved, and what they now expect |
| nudge | A small push that changed the room |
| small-decision | A call too small to score, plus what would reopen it |

Every bullet needs a `landed:` line before the session ends: a hypothesis, an initiative note, an avatar, a `4-Research/` note, a row in `5-Growth/decisions.md`, or `dropped`. An open bullet is a failed capture, not a todo for Friday.

A confidence percent you are willing to score later is the only door into `5-Growth/decisions.md`. That path goes through the braindump floor first.

## Do not file these

- "Email Sara about the demo slip."
- "Update the Jira ticket after standup."
- "Today: three meetings, shipped the one-pager, felt behind."

Those stay in the task tool or nowhere. If you cannot say where a bit lands, drop it or park one line in `4-Research/`. Do not invent a hypothesis to hold it.

## Where the rest of the work lives

- A belief you are testing → [../hypotheses/](../hypotheses/)
- A narrative with a PRD or roadmap → `3-Work/[initiative]/`
- An insight with no bet and no narrative → `4-Research/`
