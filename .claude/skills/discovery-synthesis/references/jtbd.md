# Jobs to be done (JTBD)

Understand **progress** in a situation—not demographics, not your feature list. Jobs are technology-agnostic; solutions are hypotheses.

## When to use

- Reframing feature requests ("they want export") into progress ("prove compliance without manual rework").
- Switch interviews: why they hired/fired solutions.
- Feeding segmentation ([segmentation-personas](segmentation-personas.md)) once you have many job stories.

**Skip when** you're only running usability on a known flow—job already fixed.

## Core concepts

- **Core functional job:** progress in a circumstance.
- **Emotional / social jobs:** how they want to feel or be seen.
- **Related & consumption-chain jobs:** before/after; find, buy, set up, use, maintain.
- **Forces (Switch):** Push (pain), Pull (attraction), Anxieties (fear of new), Habits (status quo).

## Statements

- **Job story:** When [situation], I want to [progress], so I can [outcome].
- **ODI outcome:** Minimize/Increase [metric] when [circumstance] while [constraint].

Keep jobs free of your product name.

## Process (compressed)

1. Scope segment + recurring situation.
2. Switch-style interviews: first thought, context, alternatives tried, choice, aftermath.
3. Extract stories with triggers, sequence, constraints.
4. Map forces per story.
5. Draft 5–10 ODI outcomes; validate language with customers.
6. Triangulate: 3+ independent stories with consistent outcomes.
7. Opportunity scoring: importance × (importance − satisfaction) per outcome.
8. Link to snapshots, synthesis, opportunities, validation plan.

## Job file

**Save as:** `4-Research/jobs/job-[handle]-[YYYY-MM-DD].md` or initiative `research/`.

Include: meta, context, forces, current solutions & failure modes, ODI outcomes, evidence (3+ stories), segment differences, scoring table, implications, links to research artifacts.

## Evidence strength

- **Stronger:** multiple recent stories, observed behavior, consistent outcome language across contexts.
- **Weaker:** hypotheticals, single anecdote, solution-laden job statements, generic complaints.

## Pitfalls

- Confusing **workflow steps** with the job.
- **Persona lock-in**—same role, different jobs in different situations.
- **Anecdote as pattern**—synthesis still required.
