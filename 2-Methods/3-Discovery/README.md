# 3-Discovery — Overview

This domain contains methods for understanding customers, framing opportunities, and validating ideas.

## Before Using Any Discovery Framework

⚠️ **Don't jump straight to research plans.**

### 1. Read the Golden Rule

**See:** [braindump.md](../../system/coaching/braindump.md) (coaching)

### 2. Braindump First (10-15 min)

**Use the prompts:** [system/coaching/prompts.md](../../system/coaching/prompts.md) — [Early — problem not yet clear](../../system/coaching/prompts.md#before-user-research--discovery).
**Or start from the entry point:** [README.md](../../system/coaching/README.md) (simple prompt for a product-thinking chat).

Quick start from that section:
- What are you actually trying to solve → Not the feature — the real problem underneath.
- Who specifically has this problem → Describe one person and their day.
- How do you know this is real → What have you actually seen or heard?

**Discovery frameworks guide your learning—they don't replace thinking.**

### 3. Then Use Discovery Frameworks

After your braindump, use the frameworks below to structure your research.

## Discovery Frameworks

- **1-Research-Interviews**  
  Interview guide and best practices. Use this before and during interviews to avoid bias, ask better questions, and capture richer stories.

- **2-Continuous-Discovery-Habits**  
  End-to-end discovery flow: create interview snapshots, synthesize patterns, create opportunities, and generate solutions. Use this when you want a repeatable weekly discovery rhythm.

- **3-Jobs-To-Be-Done**  
  Framework for capturing jobs, outcomes, and context. Use this when you need to reframe solution requests into underlying jobs and desired progress.

- **4-Opportunity-Assessment**  
  Framework for documenting early initiative thinking, capturing hypotheses, and identifying what needs validation. Use this to structure your thinking before committing to build.

- **5-Idea-Validation**  
  Framework for reducing risk before build (RAT-style validation). Use this when stakeholders say "prove it" and you need a minimal test plan for desirability, usability, feasibility, or viability.

- **6-Problem-Solution-Space**  
  Framework for systematically exploring ambiguous problems and generating multiple solution options. Use this when you need to deeply understand a problem before committing to a solution.

- **7-Segmentation**  
  Framework for grouping customers by the job they are trying to do (not demographics). Use after JTBD research to cluster job stories into 3–5 segments, then define and validate; segments drive strategy, personas (`5-Personas`) drive execution.

- **8-Product-Market-Fit**  
  Framework for understanding and achieving product-market fit. Use this to assess PMF status, validate market demand, and decide when to scale vs. iterate.

Typical flow: **Research-Interviews → Continuous-Discovery-Habits → JTBD (optional/parallel) → Segmentation (after JTBD) → Problem-Solution-Space → Opportunity-Assessment → Idea-Validation → Product-Market-Fit → Strategy/Execution**.
