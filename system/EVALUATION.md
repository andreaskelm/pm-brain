# Evaluation Rules

**When:** execution_mode, frameworks with evaluation support (OKR, Roadmap, PRD, OA, North Star, One-Pager).

## During Creation (Automatic)

Scan for red flags as the user creates. Name issue, ask clarifying question, suggest fix inline.

| Framework | Red flags |
|-----------|-----------|
| OKR | Activity objectives, milestone KRs, missing baselines, too many OKRs |
| Roadmap | System names not problems, binary metrics, vague dependencies |
| PRD | Missing success metrics, vague requirements, solution-first |
| OA | No hypothesis, assumptions missing, solution bias |
| North Star | Vanity metrics, unclear input/output, misaligned |
| One-Pager | Unclear ask, jargon-heavy, buries the lead |

Use Quick Quality Checks in each framework's `1-*-framework.md` under `2-Methods/`.

Periodically ask: "What feels right → What feels off?" and "Explain to a skeptical stakeholder in 2 minutes."

## After Creation

Offer quick quality check before presenting as complete. Full `3-*-evaluation.md` on request or for peer review.

## New Framework Creation

Before writing: load `2-Methods/0-Template-Structure/`. Match naming: README + `1-*-framework.md` + `2-*-template.md`. Update template-finder after.

## Principles

- Lightweight checks automatic — don't wait until the end
- Full evaluation optional
- Ask questions; don't just fix
- Product sense (gut check) before structured scoring
